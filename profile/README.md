# Test the world around AI agents.

An agent works inside a system you can change. **Evals AX** helps you test whether those changes help it finish the job.

[Try Vibecheck](https://evals.ax/vibecheck) · [Documentation](https://evals.ax/docs) · [CLI](https://evals.ax/docs/cli)

## Start with a task

Inspect a website for interface issues, or run an experiment with your own agent. Keep the evidence—including results that challenge the hypothesis.

```sh
evx vibecheck https://example.com --wait
```

No account needed for a public website report. [Install evx](https://evals.ax/docs/cli) with Bun, npm, pnpm or Yarn.

| Work | Start here |
| --- | --- |
| Inspect a website and follow changes over time | [Vibecheck](https://evals.ax/vibecheck) |
| Examine an API, CLI or MCP server | [Interface reports](https://evals.ax/docs/interface-reports) |
| Test a codebase's instructions against real tasks | [Context experiments](https://evals.ax/docs/use-cases#codebases) |
| Verify a task across source records and business rules | [Operations example](https://evals.ax/docs/use-cases#operations) |

## Evidence before claims

A static finding suggests something to investigate. A controlled experiment can test its effect. We preserve the protocol, agent settings and independent outcome checks so a result can be assessed within its actual scope.

Our [production API handoff study](https://evals.ax/evidence/production-api-handoff-2026-09-08) includes a verifier defect and a separate reassessment. It does not establish a performance gain. That is part of the evidence too.

Web, CLI and [API](https://evals.ax/api/v1/openapi.json) use the same account operations. [Complete Markdown docs](https://evals.ax/docs/full.md) are available for agents.
